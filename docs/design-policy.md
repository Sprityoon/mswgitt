# 상시 디자인 정책 (Design Policy)

> **무엇인가**: 한 번 확정한 뒤로 **모든 후속 작업에 계속 적용되는** 게임 디자인 결정들이다. 개별 기능 스펙(`game_design.md`)과 달리, 여기 있는 항목은 *새 기능을 만들 때마다 다시 지켜야 하는 제약*이다.

## 1. 입력·플랫폼

### ⚖️ PC/모바일 UI 레이아웃 분기 금지 — 단일 고정 레이아웃 (2026-07-15)

`IsMobilePlatform()` 등으로 런타임에 배치를 가르지 않는다. 전 플랫폼 공통 고정 레이아웃 하나만 둔다.

- 터치 타겟은 상시 **≥88px** 지향 (T62 스킬바 선례).
- 이 정책 전환으로 T52의 플랫폼 분기부가 T62로 대체됐다. 클릭 시전·이름 숨김·툴팁 기능 자체는 존치.

### ⚖️ 월드 클릭/터치 상호작용 금지 (2026-07-15, T59)

상호작용 수단은 **`F` 키(PC) / `BtnInteract`(모바일)만**이다. 사유 = UI 창과 클릭이 겹쳐 조작이 꼬였다.

- 월드 엔티티에 `TouchEvent` 상호작용을 부착하지 않는다.
- 신규 인터랙터블은 **이중 연결** 필수:
  1. 자체 `F` 핸들러 (`KeyDownEvent` — `MerchantInteract` 패턴)
  2. `InteractRequestEvent` 구독 (모바일 브리지)
- 하나만 붙이면 한쪽 플랫폼에서 조용히 조작 불능이 된다.

### 상호작용 판정 = 조준 셀 (T67 · T82)

"근처에 있으면 발동"이 아니라 **바라보는 조준 셀** 단일 기준이다.

- 판정은 `IsAimTarget` 헬퍼 단일 정의를 쓴다. 분산 핸들러가 각자 거리 판정을 두지 않는다.
- footprint는 **Trigger 월드 AABB ∩ 조준 셀 사각형**으로 자동 정합된다(T82). Trigger가 없는 대상만 기존 footprint 폴백.
- 🧭 트리거형(포탈 발밑)만 예외.

## 2. 톤 — "아늑한 생활"

이 게임의 톤은 **아늑한 생활 시뮬레이션**이다. 플레이어를 압박하는 페널티형 시스템은 채택하지 않는다.

| 결정 | 내용 |
|---|---|
| ⚖️ **날씨는 보너스만** (2026-07-11) | 비 = 작물 성장 가속 + 낚시 입질↑. **페널티 없음** |
| ⚖️ **영지 평화 원칙** | 개인 영지 안에서는 전투·피격이 없다. 몬스터 관련 장치는 사냥터·보스맵 전용 |
| ⚖️ **허기 시스템 기각** | 페널티형이라 톤과 충돌 |
| ⚖️ **도감 보상 = 최초 발견 즉시 자동 지급** (2026-07-13) | 마일스톤 누적형 미채택. Rarity 차등, `DexRewardDataSet` |

## 3. 복잡도 억제

### ⚖️ 스킬트리 단순성 가드라인 (2026-07-15 — "복잡한 구조 거부")

- **단일 부모**
- **같은 열 바로 위 행만** 연결
- **3행 × 3열 상한**

상세: [design/skill-tree-plan.md](./design/skill-tree-plan.md) §8.3. 전직 확장 계약은 동 문서 §7.

### ⚖️ Trigger 박스 1개가 3역할 겸임 — 현행 유지 (2026-07-25)

`TriggerComponent` 박스 하나가 **통행 차단 + 상호작용 범위 + walk-behind 페이드 + Y정렬 접지선**을 동시에 담당한다. 분리하지 않는다 — 단일 데이터 소스 이점 우선.

- 트레이드오프는 **의도된 것**: 충돌 박스를 튜닝하면 나머지 셋도 함께 변한다.
- Play에서 실제 불편이 확인되면 그때 분리를 검토한다.
- 박스를 만질 때의 산정 규칙은 [pitfalls.md 규칙 17](./pitfalls.md#규칙-17-trigger배치는-스프라이트-실루엣-정합이-1순위다).
