## 이어받은 상태와 반영 범위

## PC 키 변경 방식 제안 — 후속 구현 초안

공식 [키 바인딩 패키지 로컬 미러](../../../wiki/mswpackages/key-binding-package.md)의 입력 슬롯 계층을 참고한다. 샘플은 플레이어 컨트롤러 교체와 별도 저장 체계를 포함하므로 그대로 설치하지 않는다. 현재 게임의 입력은 `PlayerController.OnKeyDown`, 공격 충전/낚시 홀드 폴링, 개별 오브젝트의 F 핸들러, HUD 버튼에 나뉘어 있다. 화면 표시만 바꾸는 방식으로 구현할 수 없다.

1. 방향키 이동은 우선 고정. 점프·공격/채집·상호작용, 스킬 4칸, 가방/제작/정보/스킬/도감/보스 메뉴를 행동 ID별 기본키 표로 정의한다. 퀵슬롯 숫자키는 첫 단계에서 고정한다.
2. 키캡 선택 → 해당 행에 `새 키를 눌러 주세요` → 한 키 입력. Esc는 변경 취소. 조합키와 마우스 버튼은 첫 단계에서 지원하지 않는다. 좌우 Ctrl/Alt는 같은 키로 취급한다.
3. 중복키는 기존 행동 이름과 함께 거절한다. 방향키, 숫자키, Esc, Tab(조망), Enter/T(채팅), 시스템 단축키는 예약한다. 바꾼 뒤에도 모든 행동이 접근 가능해야 한다.
4. 단일 행동 매핑을 키다운·키업·홀드·F 분산 핸들러·HUD 키 라벨·네이티브 액션키에 모두 적용한다. 설정창에서 키를 기다리는 동안 플레이 입력을 차단한다. 모바일 `InteractRequestEvent` 경로는 그대로 유지한다.
5. 계정 `GameSettings`에 버전이 있는 키 매핑을 함께 저장한다. 서버는 허용 행동/키·중복/예약키를 다시 검사한다. 초기화는 기본키 복구, 저장 없이 뒤로는 이전 매핑 복구. 이전 세이브에 키 필드가 없으면 기본키를 사용한다.

후속 검증은 키 변경 후 실제 공격/점프/상호작용/충전/낚시/HUD 표시, 중복키 거절, Esc 취소, 저장 후 재접속, 모바일 브리지 회귀를 포함한다. 현재 창의 `키 변경 준비 중` 문구는 이 전체 경로를 구현한 뒤 제거한다.
