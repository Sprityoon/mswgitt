# 메인화면 + 슬롯 세이브 설계 (main-menu-save-slots) — 2026-08-08

> **목표**: 접속 직후 **메인화면**(키 아트 + 새로하기/이어하기)을 띄우고, **유저당 3~5개 세이브 슬롯**으로
> 서로 다른 캐릭터 진행(레벨/인벤토리/퀘스트/**영지 상태**)을 완전히 분리해 키울 수 있게 한다.
> 메인화면 아트는 제작자가 타사 에이전트로 생성 예정 — UI 뼈대는 아트 없이 먼저 만들고 `ImageRUID`만 교체한다.

---

## 1. 현 세이브 구조 실측 (2026-08-08, `PersistenceManager.mlua`)

| 항목 | 현행 |
|---|---|
| 저장소 | `_DataStorageService:GetUserDataStorage(userId)` |
| 키 | **`"SaveData"` 단일 키** — 인벤/레벨/스킬/퀘스트/영지 델타 등 JSON 블롭 1개 |
| 영지 인스턴스 | `Home_<UserId>` (map01 템플릿 런타임 복제 + 세이브의 지형/설치 델타 재생) |
| 손님 방문 | `Home_<ownerId>` 이름으로 조인 (권한 팝업 T-계열) |
| 월드 시간 | `GetGlobalDataStorage("WorldTimeStorage")`의 `AccumulatedTime` (슬롯 무관 월드 공용) |
| 입장 연출 | `UIHUDController.spawnFade` — 홈 준비 완료 신호까지 검은 커버 유지 후 페이드 |

**핵심**: 영지 상태가 전부 SaveData 델타로 재생되므로, **"슬롯 = SaveData 키를 무엇으로 읽고 쓰느냐"만 바꾸면 영지까지 통째로 분리**된다. 맵 명명(`Home_<UserId>`)은 바꿀 필요 없다(세션당 활성 슬롯 1개 전제).

## 2. 슬롯 데이터 설계

### 2.1 키 스킴 (UserDataStorage 내부)

| 키 | 내용 |
|---|---|
| `SaveData_s1` ~ `SaveData_s5` | 슬롯별 세이브 JSON (현행 SaveData와 동일 스키마) |
| `SlotMeta` | 선택 화면용 요약 JSON: `{ "1": { name, level, playSec, lastSaveTicks, fishLv }, ... }` — **슬롯 저장 시 함께 갱신** (선택 화면에서 슬롯 5개를 각각 GetAndWait하지 않기 위함 — DataStorage는 과금 자원, 호출 수 최소화) |
| `SaveData` (레거시) | **읽기 폴백 전용**. 마이그레이션 후에도 삭제하지 않는다(롤백 안전) |

### 2.2 마이그레이션 (기존 유저 보호 — 최우선 순위)

1. 로그인 시 `SlotMeta` 없음 + 레거시 `SaveData` 있음 → **슬롯 1로 간주**: `SaveData_s1`에 복사 + `SlotMeta` 생성.
2. 이후 저장은 `SaveData_s1`에만. 레거시 키는 두 번 다시 쓰지 않는다(백업 역할).
3. ⚠️ **세이브 경로 Yield 금지(규칙 9, T37 인벤토리 전량 유실)**: 마이그레이션 복사는 로그인 로드 시점(이미 GetAndWait 하는 지점)에서만. 저장 루틴에 Get을 추가하지 말 것.

### 2.3 슬롯 수

- **권고: 5 슬롯 고정** (요청 범위 3~5의 상한). 슬롯당 비용은 JSON 1개라 저장 용량 부담이 낮고, "3개 기본 + 해금" 같은 게이트는 수익 모델 없는 현 단계에서 복잡도만 늘린다. → 🙋 제작자 확정 필요.

### 2.4 슬롯이 분리하는 것 / 하지 않는 것 (명시)

| 분리됨 (SaveData 소속) | 분리 안 됨 |
|---|---|
| 레벨/XP/스탯/스킬/SP | **아바타 외형** (MSW 아바타는 계정 귀속 — 슬롯별 외형 차별화는 불가. 코스튬 저장·재적용으로 흉내내는 것은 후속 검토) |
| 인벤토리/퀵슬롯/화폐 | 월드 시간(`WorldTimeStorage` — 서버 공용) |
| 퀘스트/도감/연구 해금 | 주간 낚시왕 랭킹 (계정 단위 유지 권고 — 🙋 슬롯별로 할지 판단 필요) |
| **영지 지형 델타/설치 가구/상자 내용물** | 마을/사냥터 맵 상태 (공용) |

## 3. 메인화면(타이틀) 플로우

MSW는 월드 입장 시점에 이미 아바타가 스폰된다 → 메인화면은 **풀스크린 오버레이 UI** 방식.

```
접속 → spawnFade(검정, 기존) 유지
     → MainMenu UI 표시 (키 아트 배경 + 로고 + [이어하기] [새로하기] [슬롯 관리])
     → 슬롯 선택:
        · 이어하기: SlotMeta 요약 카드(이름/레벨/마지막 저장) 중 선택
        · 새로하기: 빈 슬롯 선택 → (선택) 영지 이름 입력 → 초기 세이브 생성
     → 서버에 ServerSelectSlot(n) RPC → 해당 슬롯 로드 → Home_<UserId> 준비
     → MainMenu 닫기 + spawnFade 페이드아웃 (기존 신호 재사용)
```

- **서버 로드 지연**: 현행은 접속 즉시 SaveData를 로드한다 → 슬롯 선택 신호가 올 때까지 로드를 보류하도록 `PersistenceManager` 진입점을 분리해야 한다. (게스트 방문 경로 `Home_<ownerId>`는 무변경.)
- 슬롯 전환은 **메인화면으로 돌아가기** 메뉴(또는 재접속)로만 — 세션 중 핫스왑 금지(저장 꼬임 방지, 규칙 9 계열).
- 삭제: 슬롯 카드 → 휴지통 → **이름 재입력 확인** 이중 확인. 삭제 = `SaveData_sN` 빈 값 덮어쓰기 + SlotMeta 제거 (물리 삭제 API 의존 금지).

## 4. UI 구성 (아트 교체 전제의 뼈대)

- 신규 `ui/MainMenuGroup.ui` (UIBuilder 저작, 규칙 6 — 기존 팝업과 동일 비주얼 아이덴티티).
  - `Bg`(풀스크린 키 아트 — 아트 나오기 전 임시 단색/기존 리소스), `Logo`, `BtnContinue`, `BtnNew`, 슬롯 카드 5장(레벨/이름/마지막 저장 표시), `BtnDelete`.
  - 키 아트는 `SpriteGUIRendererComponent.ImageRUID` 교체만으로 적용 — **UI 구조와 아트 일정 분리**.
- 메인화면 표시 중 입력 차단: `CanvasGroup.BlocksRaycasts` + HUD 숨김.
- 키 아트 프롬프트는 [art-style-guide.md §5](./art-style-guide.md) 참조 (16:9 / 1920×1080, 안전 영역 중앙).

## 6. 열린 결정 (🙋 제작자)

1. 슬롯 수 5 고정 vs 3 — §2.3 권고는 5.
2. 새로하기 시 **튜토리얼 퀘스트(101~)** 재시작 여부 — 슬롯 분리면 자연히 재시작(권고: 그대로).
3. 주간 낚시왕 랭킹의 슬롯 분리 여부 (권고: 계정 단위 유지 — 랭킹은 "사람" 단위가 자연스러움).
4. 슬롯별 영지 이름 입력 기능 (권고: v1은 "슬롯 N" 자동 명명, 이름 입력은 후속).
