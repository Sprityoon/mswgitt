## 보정 내용

기존 커스텀 타일의 문짝 보정이므로 공식 리소스로 대체하지 않았다. 열린 문의 목재·선·색감이 기준이다.

- 실내 닫힌 문20~23, 실외 닫힌 문28~31 8장 보정.
- 평평한 세로 색 띠와 붙여 넣은 듯한 긴 가로 경첩을, 유기적인 세로 나뭇결과 작은 세로 경첩으로 교체.
- 금색 링을 짙은 금속 링으로 맞추고, 세로 판재의 명암을 열린 문 계열로 통일.
- 이미지 편집 도구로 문짝을 다시 그린 뒤, 생성된 문짝 부분만 원본 문틀 안에 적용. 문틀·상인방·벽지·허리벽·돌 기단·24px 외곽 기둥은 원본 픽셀 사용.
- **후속: 열린 문24~27·32~35도8장 보정.** 첫 보정은 열린 문을 그림체 기준으로 보존해 그 안의 문짝·그림자 결함을 놓쳤다. 문짝 하단의 끊긴 사선/떨어진 조각, 바닥에 분리돼 보이던 그림자, 안쪽 판재의 띠 경계를 이미지 편집 도구로 다시 그렸다. 문짝 하단은 연속된 사선, 그림자는 그 사선에 붙은 한 덩어리다. 열림 방향·문틀·그림체는 유지했다.
- 문 영역 밖 벽·창문·바닥·24px 기둥은 그대로다. 앞서 보정한 닫힌 문8장은 후속 작업 전후 SHA-256까지 동일하다.

## 제작·검증

- 도구: 내장 `image_gen.imagegen` 닫힌 문 편집2회 + 열린 문 후속 편집1회. 닫힌 문 1차의 가로 판자와 밝은 금색을 2차에서 세로 판재·짙은 금속으로 재조정. [닫힌 문 프롬프트](06_door_repair_work/final_edit_prompt.txt) · [열린 문 프롬프트](06_door_repair_work/open_edit_prompt.txt).
- 마감: `propkit.pixelize(dot=1)`를 문 안쪽에만 적용(닫힌 문72색 / 열린 문192색, 작은 금속 하이라이트 보존). 64px 타일의 원본 프레임은 도트화하지 않는다.
- 검토1: 닫힘/열림을 128×128 원래 조립 크기와 2배 크기로 나란히 비교.
- 검토2: 8칸 벽에 문을 삽입해 문틀·벽지·목재 벽·돌 기단 연결을 비교. 타일 중앙의 가로/세로 절단선과 손잡이 가독성 확인.
- 두 변형 모두48장, 전부64×64. 닫힘/열림 변경16장 외32장은 **파일 바이트까지 동일**.
- 닫힌 문 변경 범위는 조립128×128 안의 `(35,47)~(93,126)`, 열린 문은 `(35,51)~(93,126)` 문 안쪽. 영역 밖 픽셀 변경0.
- 4장 타일을 재조립한 결과와 보정된 문 이미지의 RGBA가 완전히 같음. 절단 과정의 손실/틈 추가0.
- 기계 검증: [validation.json](06_door_repair_work/validation.json).

게임 배율·Maker 렌더 검증은 하지 않았다. 이번 결과는 PNG 아트 산출물이다.

## 재현 자료

`06_door_repair_work/`에 참조128px/512px, 생성 원본, 문짝 마감본, 편집 프롬프트, 비교 이미지와 스크립트를 보관했다.

```powershell
python prepare_reference.py
python finish_doors.py --generated generated_closed_door_final.png --open-generated generated_open_door_final.png --tag final --release
```

두 스크립트는 이 작업 폴더에서 실행한다. `finish_doors.py`는 원본 타일을 읽어 `07`·`08`과 추가 스트립만 다시 만든다.
