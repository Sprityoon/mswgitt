# MapleStory Worlds Project Agent Rules

This repository is a top-down survival/gathering/crafting game built on MapleStory Worlds (MSW).
All requests must be processed as MSW project tasks.

## 1. Rule Precedence

1. User's explicit prompt / current request
2. Project-specific rules in this document (`AGENTS.md`)
3. Loaded MSW skills and references
4. General development conventions

MSW has many silent failure modes distinct from standard game engines. Do not rely on memory or assumptions; make all technical judgments based on active project files, `.d.mlua` definitions, skill references, and Maker logs.

## 2. Task Initialization Protocol

Before performing any analysis or editing, follow this preparation sequence:

1. Load `msw-general`.
2. Load `msw-ui-system`.
3. Read the following Foundation references in full (skip if already present in the active context):
   - `msw-general/references/platform.md`
   - `msw-general/references/workspace.md`
   - `msw-general/references/entity.md`
   - `msw-general/references/authoring.md`
4. Use `msw-project` when implementing/modifying features or continuing existing work in this repository.
5. Check for known pitfalls in the quick index of [docs/pitfalls.md](./docs/pitfalls.md).
6. Deconstruct changes into verifiable steps and always include a verification step.

Requests like "다음 작업 (next task)", "이어서 진행 (continue)", "현황 (status)", or "뭐 할 차례야 (what's next)" do NOT trigger `msw-planning`. Continue work following [docs/tasks.md](./docs/tasks.md) and [docs/workflow.md](./docs/workflow.md).
`msw-planning` is reserved solely for designing a brand-new world separate from this game.

## 4. Project Fixed Specifications

- Map Mode: `RectTile` (`TileMapMode = 1`)
- Dynamic Entity Body: `KinematicbodyComponent`
- Gravity: None (0)
- Jump: `Alt` key visual jump (physics height / Z elevation does not change)
- Movement: 4-directional arrow keys
- Attack & Mining/Gathering: `Ctrl` key, targeting adjacent facing cell
- Interaction: `F` key
- Maps:
  - `map/map01.map`: Territory / Homestead origin
  - `map/town.map`: Shared town (plaza)
  - `map/template_field.map`: Hunting field
  - `map/template_boss.map`: Boss arena
- Runtime Territory Instance Name: `Home_<UserId>`
- CoreVersion Single Source of Truth: `26.7.0.0` in `Environment/config`

Do not perform batch migration on `MOD.Core, Version=...` strings in existing `.model` files even if versions are mixed.

## 5. Editing Scope & Protocols

| Target | Editing Protocol |
|---|---|
| `RootDesk/MyDesk/**/*.mlua` | Direct edit allowed |
| `RootDesk/MyDesk/**/*.csv`, `*.userdataset` | Direct edit allowed |
| `RootDesk/MyDesk/**/*.model` | ModelBuilder ONLY |
| `Global/DefaultPlayer.model` | ModelBuilder ONLY |
| `map/*.map` | MapBuilder ONLY |
| `ui/*.ui` | UIBuilder ONLY; Direct read/edit of raw JSON is strictly prohibited |
| `Global/WorldConfig.config` | Value edits only |
| `docs/**`, `game_design.md` | Direct edit allowed |

Never modify the following:
- `Environment/**`, `*.d.mlua`: API definitions, Read-Only
- `*.codeblock`, `*.directory`: Generated by Maker
- Other files in `Global/` and `common` entities
- Vendor skills registered in `skills-lock.json`

Create new `.mlua` scripts under `RootDesk/MyDesk/{Category}/Scripts/` and new `.model` files under `RootDesk/MyDesk/{Category}/Models/`. Never create new user files directly under `Global/`.

For workspace exploration, prioritize built-in agent file read and search tools. Inspect `.map`, `.model`, and `.ui` files using their respective builder read APIs. Use shell commands only for running actual programs such as `git`, `node`, or validation scripts.

## 6. MSW Core Invariants

1. Dynamic entities in `TileMapMode = 1` require `KinematicbodyComponent`.
2. Coordinates are in world units: `1 unit = 100 px`.
3. If `SpriteRUID = ""`, the entity is invisible without throwing an error.
4. When calling `SpawnByModelId`, pass a map entity such as `self.Entity.CurrentMap` as parent, never `nil`.
5. User scripts are registered as pairs of `.mlua` and Maker-generated `.codeblock`.
6. If an entity configuration is placed multiple times or spawned at runtime, create a `.model` and reference its `modelId`.
7. UI is strictly client-side. Never reference UI entities or `_LocalizationService` directly on the server.
8. `@Logic` persists across map transitions; `OnMapEnter` and `OnMapLeave` are not invoked on it.
9. Structured file edits must follow the builder's snapshot → patch → write contract.
10. Verify API names, types, and execution spaces (`ExecSpace`) against actual `.d.mlua` definitions; do not guess.

## 7. Project Absolute Rules

- **Preset First**: Always search for packages, existing models, UI templates, and resources before writing custom implementations.
- **Data-Driven**: Manage items, recipes, quantities, drop rates, and motion names via datasets or properties. Do not hardcode string branches like `if itemName == "..."`.
- **Item Key**: Inventory storage key must always be `item_dataset.Name`.
- **UserDataRow**: Use only `Count()` and `GetItem(columnName)`. `RowIndex` does not exist. Wrap optional column lookups with `pcall`.
- **Verify Definitions Before Calling**: Search actual definitions and signatures before invoking methods or accessing properties from other scripts.
- **No Yield on Save Paths**: Do not introduce extra Yield operations in save routines beyond the required `GetAndWait` / `SetAndWait`.
- **No Success Claims Without Verification**: Never describe unverified results as "working" or "normal".
- **No Out-of-Scope Refactoring**: Do not perform unsolicited structural changes, commits, or pushes.

Detailed root causes and historical incidents are maintained strictly in [docs/pitfalls.md](./docs/pitfalls.md) as the single source of truth.

## 8. Verification Protocol

Default agent verification scope:
1. Run relevant static diagnostics, linters, and builder validations.
2. Confirm `maker_refresh_workspace` returns `status ok`.
3. Check Error, Warning, and Info counts via `maker_logs(kind="build")`.
4. Verify that the build log `dateTime` matches the current refresh timestamp.
5. If creating a new `.mlua`, verify `.codeblock` generation.
6. Record results and verification scope in [docs/tasks.md](./docs/tasks.md).

Build logs may return stale snapshots. If timestamps do not match, do not claim `Error=0`; report `build 로그 갱신 미확인` (build log refresh unconfirmed). Follow [docs/workflow.md](./docs/workflow.md) for warning baselines and detailed procedures.

Build Error=0 does not guarantee `.map` serialization integrity, `.ui` rollback avoidance, or visual/collider alignment. Document structural checks and visual inspection items for the developer.

### Play Verification Policy

Play mode execution and user input simulation are strictly reserved for the human developer. Unless explicitly instructed by the developer in the current turn, do not call:
- `maker_play`, `maker_stop`
- `maker_keyboard_input`, `maker_mouse_input`
- `maker_execute_script`, `maker_screenshot`
- `maker_save`, `maker_move_map`
- `maker_reset_data_storage`, `maker_import_maplestory_map`

If Play was not executed, explicitly state: `런타임 검증 보류(제작자 수행)` (Runtime verification pending: developer execution).
If MCP is not connected, complete available static verification and state: `refresh 검증 보류` (Refresh verification pending).

## 9. Operations & Security

- Team structure: 1 Developer + AI Assistant.
- Subagents may only be spawned when explicitly requested by the developer.
- Do not issue new T-numbers. Legacy T-numbers are reserved solely as archive identifiers in `docs/agents/`.
- Never commit MCP configuration files containing tokens (e.g., `.mcp.json`, `.cursor/mcp.json`).
- If an intermediate step fails, halt progression and resolve the root cause before continuing.
