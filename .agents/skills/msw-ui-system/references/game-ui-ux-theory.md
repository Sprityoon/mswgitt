# 게임 UI/UX 핵심 이론 및 MSW 설계 프레임워크 (Game UI/UX Theory & Framework)

> **문서 목적**: 학술적·산업적 게임 UI/UX 이론(Fagerholt & Lorentzon 4분면 모델, Celia Hodent 인지신경과학 프레임워크, 정보 역피라미드, Contextual HUD, 글로벌 접근성 표준 XAG)을 체계화하고, 이를 **메이플스토리 월드(MSW) 2D 탑다운 생활·크래프팅 RPG 환경**에 최적화하여 구현하기 위한 실무 표준 지침서이다.

---

## 1. Fagerholt & Lorentzon의 4분면 UI 분류 모델 & MSW 매핑

Erik Fagerholt & Magnus Lorentzon(2009)의 마스터 논문 *Beyond the HUD*에서 확립된 이론으로, **게임 내러티브 세계관(Diegesis)**과 **표시 공간(2D 스크린 vs 월드 공간)**의 2개 축으로 UI 요소를 4분면으로 구분한다.

```
                  게임 세계관 내 존재 (Diegetic)
                                │
          [ Diegetic ]          │          [ Spatial ]
   게임 캐릭터도 보고 인지함   │   캐릭터는 인지 못하나
   월드 오브젝트 자체에 통합   │   월드 공간(2D 좌표)에 투영
                                │
월드 공간 (In World Space) ─────┼───── 스크린 공간 (Screen Space)
                                │
            [ Meta ]            │       [ Non-Diegetic ]
   캐릭터의 신체/심리 상태를    │   전통적인 2D 스크린 오버레이
   화면 렌더링 효과로 투영     │   캐릭터는 모르는 순수 플레이어 정보
                                │
                게임 세계관 외 (Non-Diegetic)
```

### MSW (MapleStory Worlds) 실전 구현 매핑

| 분류 | 이론 정의 | 대표적 상용작 사례 | 메이플스토리 월드(MSW) 실전 적용 방안 | MSW 기술 스택 / 컴포넌트 |
|---|---|---|---|---|
| **Diegetic** (다이제틱) | 게임 내 세계관에 실재하며 게임 캐릭터도 직접 보거나 듣고 상호작용하는 UI | *Dead Space* (척추 네온 체력바, 홀로그램 RIG), *Fallout* (손목의 Pip-Boy), *Metro* (손목시계/나침반) | • **모닥불 연소**: 잔여 시간에 따라 불씨 크기 및 연기 높이 단계적 축소<br>• **작물/묘목 성장**: 4단계 스프라이트 전이(`SpriteRUID` 변경)<br>• **도구 내구도**: 손에 든 도구의 픽셀 균열/파손 외형<br>• **제작 화로**: 가동 중일 때 굴뚝 연기 파티클 발생 | `SpriteRendererComponent`<br>`areaParticle`<br>World Entity Sprite Animation |
| **Non-Diegetic** (논다이제틱) | 게임 세계 밖에 존재하며 플레이어의 편의를 위해 2D 스크린 오버레이로 제공되는 전통적 UI | 일반적인 RPG의 체력 게이지, 화면 모서리 미니맵, 퀵슬롯 바, 가방 창 | • **좌상단**: 프로필 아바타 + HP/MP 바 + 퀘스트 트래커<br>• **하단 중앙**: 10칸 슬림 핫바 (도구 내구도 바 + 소모품 수량 카운터)<br>• **우하단**: 메인 액션(공격/채집) + 아치형 Q/W/E/R 스킬 클러스터<br>• **우상단**: 날씨/시간 위젯 + 나침반 미니맵 | `UIGroup` (Screen Space)<br>`SpriteGUIRendererComponent`<br>`TextGUIRendererComponent`<br>`ButtonComponent` |
| **Spatial** (스페이셜) | 게임 캐릭터는 인지하지 못하지만 월드 좌표(2D/3D 공간)의 특정 오브젝트에 고정·투영되는 UI | *The Division* (증강현실 홀로그램 경로선), *Persona 5* (캐릭터 발밑 3D 타겟 메뉴) | • **조준 셀 인디케이터**: 조준된 타일/오브젝트 상단에 뜨는 `[F]` 상호작용 말풍선<br>• **전투 피드백**: 타격 위치에 튀어 오르는 데미지 스킨 텍스트<br>• **엔티티 상태**: 몬스터 머리 위 실시간 미니 HP바<br>• **월드 네임택**: 엔티티 발밑/머리 위 이름 및 칭호 | `World Space` UI<br>또는 카메라 좌표 추적 World-to-Screen 변환 UI<br>`DamageSkin` / Floating Text |
| **Meta** (메타) | 세계관 내 사건(신체/환경 변화)을 플레이어의 화면 전체 연출(2D)로 투영하는 인터페이스 | *Call of Duty* (피격 시 화면 붉은 핏자국 펄스), *Tomb Raider* (저체온증 시 화면 가장자리 서리) | • **위기 체력(HP < 25%)**: 화면 외곽 붉은 비네팅(Vignette) 펄스 연출<br>• **혹한/눈보라 날씨**: 화면 가장자리에 얼어붙는 서리 텍스처 오버레이<br>• **야간/동굴 탐험**: 플레이어 램프 반경 외곽을 어둡게 가리는 원형 마스크 시야 | 화면 전체를 덮는 Fullscreen Panel<br>`MaskComponent`<br>`CanvasGroupComponent` (알파 페이드) |

> **MSW 설계 원칙**: 무조건적인 Non-Diegetic HUD 배치를 지양하고, **Spatial(조준 셀 F 말풍선, 몬스터 머리 위 HP)과 Diegetic(불씨 크기, 작물 성장 외형)을 적극 도입**하여 화면 클러터를 억제하고 플레이어의 시선이 월드 중심에 머물도록 유도한다.

## 2. 인지 신경과학 기반 게임 UX 프레임워크 (Celia Hodent)

전 Epic Games UX 디렉터이자 인지심리학자인 Celia Hodent(*The Gamer's Brain*)의 프레임워크는 플레이어의 뇌가 정보를 지각하고 처리하는 한계(Perception, Attention, Memory)를 극복하기 위해 **Usability(사용성)**와 **Engage-ability(몰입성)**의 두 축을 제시한다.

```
                        ┌────────────────────────────────────────┐
                        │      Game UX Framework (Celia Hodent)  │
                        └───────────────────┬────────────────────┘
                                            │
               ┌────────────────────────────┴────────────────────────────┐
               ▼                                                         ▼
    [ Usability (사용성) ]                                    [ Engage-ability (몰입도) ]
  외재적 인지 부하(Extraneous Load) 제거                    자기결정성 이론(SDT) & 몰입(Flow)
  - 정보 지각 용이성 (Perception)                           - 자율성 (Autonomy): 자유로운 선택
  - 직관적 조작 반응성 (Motor Control)                     - 유능감 (Competence): 성장과 피드백
  - 명확한 멘탈 모델 (Mental Model)                         - 관계성 (Relatedness): 교류와 협력
```

### 1) 인지 부하 이론 (Cognitive Load Theory)과 MSW 제어 전략
인간의 작업 기억(Working Memory)은 극히 제한적(동시 약 4±1개 정보 단위)이다. 인지 부하를 세 가지로 분리하여 관리해야 한다:

1. **Intrinsic Load (내재적 부하 - 게임 본연의 재미)**:
   - 게임 규칙, 보스의 패턴 회피, 크래프팅 최적화 경로 계산 등 **플레이어가 즐겨야 하는 의도된 지적 도전**.
   - *MSW 전략*: 과도하게 복잡한 다층 조합식을 지양하고, 3단계(기초 재료 → 가공품 → 최종 장비) 이내의 명쾌한 제작 트리를 유지한다.
2. **Extraneous Load (외재적 부하 - 나쁜 UI로 인한 낭비)**:
   - 모호한 아이콘, 산만한 HUD 배치, 작은 터치 타겟, 복잡한 메뉴 뎁스로 인해 **플레이어가 헤매면서 소모하는 불필요한 정신적 피로**.
   - *MSW 전략 (Zero Extraneous Load 원칙)*:
     - PC/모바일 단일 고정 레이아웃으로 기기별 학습 비용을 단일화.
     - 모든 터치 타겟은 최소 **88×88px** 이상 확보하여 빗나간 터치 방지.
     - 월드 직접 클릭 금지: 조준 셀 + 단일 상호작용 키(`F` / `BtnInteract`)로 조작 갈등 완전 해소.
3. **Germane Load (본질적 학습 부하 - 스키마 형성)**:
   - 시스템의 동작 원리를 이해하고 패턴을 습득하는 긍정적 학습 과정.
   - *MSW 전략*: 아이템을 최초 획득했을 때 도감에 즉시 등록되며 반짝이는 팝업과 효과음이 발생하도록 하여(도감 즉시 보상 규칙), 플레이어가 새로운 아이템 탐색의 가치를 즉시 학습하도록 촉진.

### 2) Usability 4대 필수 지침

- **Affordance & Signifiers (행동 유도성과 기표)**:
  - 인터랙션 가능한 오브젝트(나무, 바위, 작업대)는 바라보는 순간 조준 셀 테두리와 `[F]` 키 아이콘이 즉시 떠올라야 한다.
  - 클릭 가능한 버튼은 앤틱 우든 테두리와 골드 림, 명확한 입체 음영을 갖추어 '눌릴 수 있음'을 무의식적으로 직관시킨다.
- **Consistency (일관성)**:
  - 색상 코드, 버튼 양식, 폰트 크기, 창 닫기 동작(ESC 키 / 우상단 X 버튼)은 게임 전체에서 100% 동일해야 한다.
  - 양피지 톤앤매너(Parchment + Carved Wood + Gold Trim)를 모든 팝업 창에 엄격히 계승한다.
- **Feedback Loop (실시간 피드백 루프)**:
  - 모든 사용자 입력(클릭, 키 입력, 터치)은 **0.1초(100ms) 이내**에 시각(스프라이트 눌림 프레임) 및 청각(클릭 사운드) 피드백을 반환해야 한다.
  - 쿨다운 중인 스킬은 `SpriteGUIRendererComponent.FillAmount`를 통해 회전하는 어두운 마스크로 잔여 시간을 명시한다.
- **Error Prevention & Recovery (오류 방지 및 복구)**:
  - 고가치 장비나 희귀 아이템을 분해·폐기할 때는 반드시 "정말 폐기하시겠습니까?" 2차 확인 모달을 띄운다.
  - 가방이 가득 찬 상태에서 채집 시 "가방에 빈 공간이 없습니다" 토스트 알림을 즉각 노출하여 자원 유실을 방지한다.

## 3. 인지 부하 분산과 정보 역피라미드 구조 (Information Hierarchy)

플레이어의 시선 추적(Eye-tracking) 연구에 따르면, 게임 플레이 시간의 **약 80%는 화면 중앙의 캐릭터 및 액션 영역에 집중**되며, 주변부 HUD를 확인하는 데는 단 20%의 주의만 배분된다. 따라서 정보의 시급성과 중요도에 따라 4단계 계층으로 분산 배치해야 한다.

```
       [ Tier 1: Critical (초 단위 즉각 정보) ]
    ─────────────────────────────────────────────
    중심 시야 반경 내 / 캐릭터 머리 위 / 조준 셀
    - HP 위기 경고, 피격 방향, 스킬 쿨다운 완료 플래시, 조준 F 프롬프트
         │
         ▼
       [ Tier 2: Tactical (전술 보조 정보) ]
    ─────────────────────────────────────────────
    주변부 HUD (화면 모서리 및 상단)
    - 미니맵, 날씨/시간 위젯, 퀘스트 요약, 버프/디버프 타이머, 핫바 슬롯
         │
         ▼
       [ Tier 3: Strategic (전략/관리 메뉴) ]
    ─────────────────────────────────────────────
    필요 시 능동적으로 여는 전체/팝업 창
    - 가방(I), 제작(C), 스킬트리(K), 퀘스트 저널, 영지 관리
         │
         ▼
       [ Tier 4: Meta (시스템 설정) ]
    ─────────────────────────────────────────────
    게임 외부 설정 및 관리
    - 그래픽/오디오 설정, 조작키 매핑, 접근성 옵션, 게임 종료
```

## 4. 최신 HUD 설계 트렌드 & MSW 패턴 (Dynamic / Contextual HUD)

*Argentics Game HUD Design 분석*과 최신 콘솔 명작(Elden Ring, Ghost of Tsushima, Zelda BotW)의 공통 트렌드는 **"정적 HUD의 축소와 상태 반응형(State-driven) 동적 HUD"**이다.

### 1) 상황 반응형 상태 머신 (Contextual FSM)
플레이어의 행동 컨텍스트에 따라 HUD 컴포넌트의 가시성(Visibility)과 불투명도(Alpha)를 자동으로 전환한다:

| 플레이어 상태 | 노출되는 HUD 요소 | 숨김/페이드아웃 요소 | 의도 및 플레이어 경험 |
|---|---|---|---|
| **평상시 탐색** (Exploration) | • 나침반 미니맵 (반투명)<br>• 날씨/시간 위젯<br>• 10칸 핫바 (알파 50%) | • HP/MP 게이지 (체력 100% 시 숨김)<br>• 전투 스킬 클러스터 (알파 축소)<br>• 퀘스트 상세 텍스트 | 화면 개방감과 자연 그래픽 몰입 극대화. 아늑한 생활 시뮬레이션 감성 전달 |
| **전투 진입 / 피격** (Combat) | • 플레이어 HP/MP 바 100% 노출<br>• 타겟 몬스터 HP바 활성화<br>• 스킬 쿨다운 클러스터 100% 노출 | • 퀘스트 상세 가이드<br>• 날씨/제작 토글 버튼<br>• 채팅창 프리뷰 | 전투 조작에 필요한 Critical 정보에만 시선 집중. 시각적 노이즈 차단 |
| **작업 / 제작** (Harvest/Craft) | • 도구 내구도 게이지 강조<br>• 획득 자원 플로팅 카운터<br>• 제작 레시피 가이드 | • 미니맵 축소<br>• 전투 스킬 클러스터 비활성화 | 채집 효율 및 잔여 도구 수명에 집중 |

### 2) 환경 및 다중 채널(Multi-modal) 통합 가이드
- **인위적 화살표 배제**: 바닥에 번쩍이는 네온 화살표 대신, 바람에 날리는 단풍잎 파티클의 방향이나 굴뚝 연기, 강물의 흐름으로 랜드마크의 방향을 유도한다.
- **사운드 스케이프 연동**: UI 사운드는 단순한 비프음이 아니라, 양피지 바스락거림, 원목 서랍 열리는 소리, 골드 코인 짤랑이는 소리를 사용하여 아늑한 판타지 세계관에 동화시킨다.

## 6. 글로벌 게임 접근성(Accessibility) 표준: XAG 기반 MSW 실전 지침

마이크로소프트의 **Xbox Accessibility Guidelines (XAG)** 및 전 세계 플랫폼 홀더들의 필수 준수 표준을 MSW 프로젝트에 맞게 재해석한다.

### 1) XAG 101/102: 텍스트 가독성 및 대비율 (Text Display & Contrast)
- **최소 대비율 4.5:1 준수**:
  - 양피지(Parchment: `#F5E6C8`) 배경 위 본문 텍스트는 짙은 갈색(`Dark Brown: #3E2723` 또는 `#2B1810`)을 사용하여 7:1 이상의 고대비를 유지한다.
  - 게임 월드(배경 스프라이트) 위에 바로 뜨는 텍스트(데미지 스킨, 이름표)는 배경색과 섞이지 않도록 **반드시 2px 이상의 검은 외곽선(Outline) 또는 반투명 어두운 백플레이트 패널**을 둔다.
- **최소 폰트 크기**:
  - 모바일 해상도(1920×1080 기준)에서 최소 본문 크기는 **24pt 이상**, 핵심 수치는 **32pt 이상**으로 설정하여 작은 화면에서도 가독성을 보장한다.

### 2) XAG 112/113: 포커스 및 네비게이션 일관성 (Focus & Navigation)
- **명확한 포커스 하이라이트**:
  - 버튼이나 퀵슬롯이 선택/호버되었을 때 테두리가 황금색(`#FFD700`)으로 빛나며 크기가 1.05배 확대되는 펄스 애니메이션을 부여한다.
- **단일 탈출 경로 (Back Route Consistency)**:
  - 어떤 복잡한 팝업 메뉴(스킬트리, 도감, 상점)라도 **우상단 명확한 [X] 닫기 버튼**과 **키보드 [ESC]** 키 누름으로 즉시 닫힐 수 있어야 한다.

### 3) Multi-channel Cueing (다중 감각 정보 전달 원칙)
- **색각 이상(색약) 대응**:
  - 정보의 상태(성공, 실패, 위험, 등급)를 **색상 단독으로만 표현하는 것을 엄격히 금지**한다.
  - *예시 (체력 부족 경고)*: 붉은색 게이지 + 심장 박동 아이콘 깜빡임 + 위기 비프음 + 화면 가장자리 비네팅 펄스의 4중 채널 동시 전달.
  - *예시 (아이템 등급)*: 색상 테두리(일반-흰색, 희귀-파란색, 전설-황금색)와 함께 **등급 텍스트(Common, Rare, Legendary)** 및 **별(★) 개수**를 항상 병기한다.

## 7. MSW UI/UX 제작 및 자체 검증 체크리스트 (The 10 Golden Rules)

모든 `.ui` 및 UI 관련 `.mlua` 작성 후 반드시 확인해야 하는 자가 점검표:

1. [ ] **4분면 분산**: 화면 전체가 Non-Diegetic UI로 뒤덮이지 않았는가? 조준 셀 인디케이터나 월드 피드백 등 Spatial/Diegetic 요소가 적절히 분담하고 있는가?
2. [ ] **외재적 인지 부하(Extraneous Load) 억제**: 불필요한 아이콘이나 겹치는 텍스트 없이 화면이 정돈되어 있는가?
3. [ ] **정보 계층(Hierarchy)**: 플레이어 생명선(HP/MP, 피격)이 중심 시선 반경 내에 있고, 관리 메뉴(가방, 제작)는 필요 시에만 열리는가?
4. [ ] **터치 타겟 규격**: 모바일 환경을 고려하여 모든 인터랙티브 버튼의 크기가 **가로/세로 88px 이상**인가?
5. [ ] **톤앤매너 일관성**: 앤틱 우든 프레임, 골드 림, 양피지 텍스처 스타일이 프로젝트 전체 규격과 일치하는가?
6. [ ] **텍스트 명도 대비**: 배경과의 명도 대비가 4.5:1 이상이며 외곽선 처리가 되어 있어 글자가 또렷하게 읽히는가?
7. [ ] **다중 채널 전달**: 중요한 상태(쿨다운, 체력 위기, 재료 결핍)가 색상뿐 아니라 형태(아이콘), 텍스트, 사운드로 함께 전달되는가?
8. [ ] **실시간 반응성**: 버튼 클릭 시 0.1초 내 비주얼(스프라이트 누름) 및 오디오(클릭음) 피드백이 발생하는가?
9. [ ] **단일 탈출 보장**: 모달/팝업 창이 ESC 키 및 우상단 X 버튼으로 안전하게 닫히는가?
10. [ ] **빌더 무결성**: `.ui` 파일이 직접 수기 편집되지 않고 `UIBuilder` API를 통해 빌드 및 자동 린트(`ui_lint.cjs`)를 통과하였는가?
